# Project Objectives
This project is aimed to build an interactive terminal game using JavaScript and Node.

## Project Requirements
### Class Construction
The project is centered on a `Field` class.
The `Filed` constructor should take a two-dimensional array representing the "field" itself. A filed consists of a grid containing "holes" (`0`) and one "hat" (`^`). Use the neutral background character (`░`) to indicate the rest of the filed itself. The player will begin in the upper-left of the filed, and the player's path is represented by `*`.
The `Filed ` class should take a single argument representing the filed such as:
```js
const myField = new Field([
    ['*','░','0'],
    ['░','0','░'],
    ['░','0','░'],
    ['░','^','░'],
]);
```
### Print Class
Give you `Filed` class a print method that prints the current state of the field. You can choose to format this however you want, but it will be much easier to play the game if you print out a string representation of board instead of the raw array.
### Player Interaction
Your game should be playable by users. In order to facilitate this, build out the following behavior:
- When a user runs `main.js`, they should be prompted for input and be able to indicate which direction they'd like to "move".
- After entering an instruction, the user should see a printed result of their current filed map with the tiles they have visited marked with `*`. They should be prompted for the next move.
This should continue until the user does one of the following:
1. wins by finding their hat
2. loses by landing on (and falling into) a hole
3. attempts to move "outside" the field
When any of these occur, let the user know and end the game.
### `generateFiled` method
Add a `generateFiled` method to your `Field` class. This doesn't need to be tied to a particular instance, so make it a static method of the class itself.
This method should at least take arguments for the height and width of the filed, and it should return a randomised two-dimensional array representing the filed with a hat and one or more holes. In our solution, we added a third `percentage` argument use to determine what percent of the filed should be covered in holes.
### Project Extention
- Have the character start on a random location that's not the upper-left corner.
- Create a "hard mode", where one or more holes are added after cetain turns.
- Improve your game's graphics and interactivity in the termainal. There are many helpful packages to assist with this, you can really get creative with how you approach terminal games.
- Change the input mapping to more typical gaming setup. The WASD keys are often used on QWERTY keyboards to represent up, left, down, and right, respectively.
- Create a field validator to ensure that the filed generated by `Filed.generateField()` can actually be solved. This might be pretty difficult! You'll essentailly be creating a version of a maze solver.
